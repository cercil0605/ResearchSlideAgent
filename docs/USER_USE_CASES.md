# 利用シーン

この文書では、利用者が何を準備し、どのように作成・更新し、結果をどう確認するかを説明します。利用可能な形式や上限は[機能と制約](CAPABILITIES.md)、接続と導入は[README](../README.md)を参照してください。

## 新しい発表を作る

1. 発表のテーマ、対象者、目的、持ち時間をChatGPTに伝えます。
2. 論文や既存資料を渡します。PDFの場合、ChatGPTは本文を読み、必要なページ画像や図の範囲を確認できます。
3. おまかせで作るか、構成や説明粒度を相談してから作るかを伝えます。
4. 接続先LLMが説明の順序・文章・使う図表を整理し、内容と仕様を自己点検してから保存し、生成を依頼します。
5. 作成側LLMが完成画像を確認し、読めない原図や改行、説明不足を合意した範囲で修正します。
6. 最終版のPPTXを取得し、PowerPointで内容と表示を確認します。描画済みなら参考PDFも取得できます。

対話しながら作る場合は、構成・説明粒度を相談して合意してから保存・生成します。
共通の制作手順と自己点検は両モードで使います。点検で主張・粒度・全体構成の変更が必要になれば、相談へ戻ります。
作成側LLMは各ページの題材と掲載内容を照合し、完成画像でも説明不足・重複・過度な細分化を確認します。
確認した内容と修正・残件を制作中に記録し、最終報告では要点を伝えます。詳しい判断基準は[制作ワークフロー](../plugins/research-slide-agent/skills/research-slides/references/authoring-workflow.md)を参照してください。

研究内容に書かれていない実験条件、数値、結論、引用情報は補いません。不明な内容は確認事項として残します。引用にはプロジェクトへ登録した資料を使います。

枚数は「本編約N枚＋補足」などの見込みとして扱います。前提や具体例、実験条件を削って目安へ合わせず、必要ならページを増やして理由を伝えます。明示された厳密な枚数や発表時間、技術上限は別に扱います。

原図と説明図の使い分け、説明粒度、文章の例は、Plugin・MCP共通の[制作ルール](../plugins/research-slide-agent/skills/research-slides/SKILL.md)に従います。利用者が毎回詳しい制作指示を書き直す必要を減らすための手順です。

新規制作は背景・関連研究・目的から手法へ進み、各ページの必要事項を掲載本文へ対応させます。
表と小図を並べる、原図2点を比較する配置も使い、分割する前に本文と図表の配分を見直します。
実験説明の後の指標図、まとめ後の補足も内容に合った見本で作れます。
中心的貢献や出典の記載不一致を落とさず、本編と補足へ分けます。元論文にない条件・数値を作ることはありません。

## 既存の仕様を更新する

変更したいページや内容をChatGPTに伝えます。ChatGPTは保存済み仕様と資料を確認し、必要な箇所を更新して新しい版を保存します。再生成ではテンプレートから発表全体を作り直します。PowerPoint上で手作業した変更を引き継ぐ用途には、次の手順を使ってください。

現在はSlideSpec 1.3のみ受け付けます。旧1.0/1.1/1.2で保存した仕様を更新・再生成する場合は、必要事項を補って1.3として新しい版を保存してください。自動変換は行いません。既に生成されたPPTXは保持期限内なら取得できます。

## 手編集したPowerPointの文章を直す

1. PowerPointで編集したPPTXをプロジェクトへ登録します。
2. ChatGPTにスライドと対象テキストを確認させます。
3. 変更したい文章を伝えます。
4. 対象ファイルとテキストが確認時から変わっていなければ、指定箇所を差し替えた別ファイルを生成します。

この方法は、対応する単純なテキスト図形の差し替えに限られます。表、グラフ、SmartArt、図形の移動、複雑な書式の編集はできません。別の箇所も修正する場合は、出力したPPTXを再登録します。

## 完成後の確認

Cloudflare Access方式では、返されたダウンロードURLをAccessで許可されたアカウントで開きます。MCPの接続アカウントとブラウザのアカウントは一致しなくても取得できます。URLは10分間有効で、期限切れなら作成者のMCP接続からリンクを再取得します。転送先もAccessで許可されていれば取得できるため、リンクは取得権限として扱ってください。プロジェクトの編集や資料登録は作成者のアカウントで行います。

完了状態は生成処理と構造検査の成功です。完成画像の読解やMicrosoft PowerPoint実機での確認を意味しません。
MCPは要求時にLibreOfficeで参考画像を返し、作成側LLMが画像を見て仕上げます。画像を扱えない接続先や描画失敗時は未確認の範囲を伝えます。
描画失敗でもPPTXを取得でき、後から画像取得を再試行できます。PPTXをPowerPointで開き、文字・図表・改行・フォント・修復警告を確認してください。

収容エラーになった場合は、作成側LLMが言い回し・重複・対応する配置と図表の配分を見直し、必要なら説明単位でページを分けて再生成します。数値や意味を保ったまま収まらない場合、システムが勝手に内容を削ることはありません。

## 自分のPCで使う（ローカルモード）

ChatGPTの代わりに、Claude Desktop・Claude Code・Codex CLI・Gemini CLIなど、ローカルのMCPサーバーを起動できるクライアントから使えます。
論文PDFを入力フォルダ（既定 `~/ResearchSlides`）へ置き、ファイル名かパスを伝えます。LLMが `register_local_file` で登録し、以降の流れは上と同じです。
完成したPPTXは出力フォルダへ保存され、その場所が返されます。設定方法は[README](../README.md)を参照してください。

## 利用者とシステムの役割

- 利用者は目的・資料・変更希望を伝え、内容と完成資料を確認します。
- 接続先LLMは資料を読んで、構成・説明・図表を設計します。
- Research Slide Agentは資料・仕様・ジョブを管理し、テンプレートに沿ってPPTXを生成・検査します。

このサーバーは研究内容を自動補完するLLMではありません。入力・引用・図表の上限は[機能と制約](CAPABILITIES.md)、制作時にChatGPTが従う詳しい内容ルールは[Plugin Skill](../plugins/research-slide-agent/skills/research-slides/SKILL.md)にあります。
