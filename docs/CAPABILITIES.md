# 機能と制約

この一覧は、現行コードで確認できる利用者向けの範囲を示します。テンプレート固有の挙動は[テンプレート詳細](TEMPLATE_AND_CONTENT_RULES.md)、MCP契約は[API](../API.md)が詳しい説明です。

## PowerPointの生成

| 機能 | 現在の範囲 |
|---|---|
| テンプレート | 同梱の正本テンプレートを使い、見本ページを複製して内容を差し替える |
| 枚数 | 作成枚数の見込みは目安とし、必要な説明を削らずページを分ける。1ジョブ40枚は技術上限で推奨枚数ではない。超える場合は内容を圧縮せず制約を示す |
| 研究発表の構成 | 1.3は概要→背景→関連研究→目的→手法の順序と掲載内容の対応を検査。複数実験と補足に対応。旧1.0/1.1/1.2は廃止 |
| 一般向け構成 | 正本のページ見本から必要なものを選ぶ。研究発表用の架空の背景・実験は作らない |
| 表 | 1.3は1～3列と領域内に収まる行数。文字・揃え・余白・罫線を保ち、列幅と必要な行高を配分。4部位も同じ表にできる |
| 図 | 1.3は表＋原図／説明図、または原図2点の配置にも対応。編集可能な説明図にも対応。手順・分岐・集約・比較をノードと接続線で示す。最大12ノード・6段・同じ段に4ノード。前向きの隣接段のみ接続でき、循環・逆向き・段を飛ばす接続・独自強調は未対応。図枠への収まりも検査する |
| グラフ | 直接生成は未対応 |
| 文字の収まり | フォント幅の保守的な見積もりで検査する。内容を黙って切ったり、文字を縮小したりせず、意味を保つ言い換えまたはページ分割を求める。先に適したcompositionや図表と本文の配分を検討する。正本の箇条書きと重なる手入力の記号は修正を求める |
| 図の配置 | method（図と本文）、results_figure（大きい図）、overview（本文3群とキー図）を各sectionで再利用。1.3はmethodの本文領域にtext_visual/table_visual/two_imagesを選べる。マスター・ロゴ・題名・番号・文字書式は維持 |
| 制作の確認情報 | 全体保存・1枚差し替えの両方で、保存前に掲載先を検査し、図の不足等の警告、引継ぎ見出しと図枠寸法を返す。1.3は節と掲載内容の対応も返す。内容の意味・可読性の自動合格判定ではない |
| 生成後の画像 | get_slide_previewが要求時にPDF/PNGを近似描画。同じPPTXの結果を再利用。個別頁と6頁までの一覧に対応。参考PDFは描画後に取得可能。作成側LLMが画像を確認して仕上げる。PPTXの生成完了は画像確認の合格を意味しない |

研究発表の確認情報には表示タイトルと論文の節を併記し、ページ内の未指定役割・同じ本文への複数役割の対応を示します。
手法への大図見本の使用や、同じ節・列見出しの隣接表に1行だけのページがある場合も見直し候補を返します。
助言は保存を妨げず、タイトルの翻訳一致や内容の充足、表の統合可否を自動判定するものではありません。
表示タイトルへ発表の構成名を残す[制作指示](../plugins/research-slide-agent/skills/research-slides/references/presentation-guidelines.md#r13-大タイトルで発表の構成を示す)がありますが、現行コードはsectionとtitleの対応を強制しません。
収容エラーの案内は、必要な事実を保ち、言い換え・見本・図と本文の配分を見直してから意味単位で分割する順序を示します。
ページの説明充足・関連研究の区別・分割前の配置判断・完成画像での内容点検は、[制作ワークフロー](../plugins/research-slide-agent/skills/research-slides/references/authoring-workflow.md)に従って作成側LLMが行います。
これはLLM向けの制作規約であり、サーバーによる内容の自動補完・合格判定ではありません。

## 入力資料と保存

| 項目 | 現在の範囲 |
|---|---|
| 形式 | PDF、PPTX、PNG、JPEG、CSV、XLSX |
| ファイル数 | 元資料10件まで。PDFから派生した画像は別枠で80件まで |
| 容量 | 1ファイル20 MiBまで、プロジェクト合計100 MiBまで |
| PDF | 最大500ページ。テキスト抽出とページ画像表示、領域切り出しに対応。スキャン画像のOCRはしない |
| 抽出 | 参照元のテキストをページ・シート単位で最大24,000文字返す。長い場合は切り詰め状態を返す |
| 保持 | プロジェクトは作成後7日でアクセス拒否・削除の対象になる |

入力の安全性確保のため、マクロ、有効な外部Office参照、暗号化PDF、危険な圧縮構造などは拒否します。詳しくは[Security](../SECURITY.md)を参照してください。

## 更新・修正

| 機能 | 現在の範囲 |
|---|---|
| 仕様からの再生成 | 1.3の仕様から正本テンプレートで全体を再生成。旧保存仕様は1.3での再作成・保存が必要。生成済みPPTXは保持期限内なら取得可能 |
| PowerPointで手編集した資料 | 最新版として再登録し、検査で特定できる単純なテキスト図形を差し替える |
| 部分修正の対象外 | 図形の移動・サイズ変更、表・グラフ・SmartArt、複雑な書式付きテキストなど |
| 競合検出 | 仕様版、対象テキストのハッシュ、パッチ元ファイルを照合し、変更後の対象には適用しない |
| 再試行・同時実行 | 利用者ごとに同時ジョブ1件。失敗ジョブは上限内で再試行できる。worker上限は設定で1または2 |

## 認証・運用状況

Cloudflare Access方式と、既存OAuth認可サーバーを使う方式を実装しています。自分のPCのMCPクライアントから認証なしで使うローカルモード（`rsa local`、stdio）もあります。資料は許可した入力フォルダから登録し、成果物は出力フォルダへ保存します。開発用の認証なしモードはloopback接続に限定されます。外部サービスの設定やChatGPTとの実接続が受け入れ済みかどうかは[Testing](../TESTING.md)を参照してください。

Cloudflare方式の成果物（PPTX・参考PDF・PNG）は、Accessで許可された利用者が10分間有効な署名付きURLを持っていれば取得できます。MCPの作成者とブラウザのアカウントが異なっても取得可能で、アカウント紐付けは不要です。URLを転送した相手もAccessの許可対象なら取得できます。プロジェクト操作・URL発行・資料登録の所有者検査は維持します。

現在の保存・ジョブ構成はSQLiteとAPI／workerです。GCP版は未実装で、[GCP資料](../deploy/GCP.md)は移行時の検討事項です。

## 詳細な制約（READMEから移動）

- 1ジョブの技術上限は40枚（推奨枚数ではない）。必要な説明が超える場合は省略せず制約を明示する。アップロード資料10件＋派生画像80件、各20 MiB、両者合計100 MiB。ユーザー同時ジョブ1、研究室実行上限2。
- PDF/PPTX/PNG/JPEG/UTF-8 CSV/XLSX。資料抽出は1回24,000文字まで。画像PDFのOCRは未対応。
- SlideSpec 1.3のネイティブ表、ノードと接続線の説明図、元画像と複合配置に対応します。グラフの直接生成は未対応です。
- 部分修正は、明示フォントを持つ単純なトップレベルのテキスト図形のみ。複数ラン・グループ・SmartArt・表/グラフの部分更新は停止する。
- 再生成は正本の見本ページを複製します。手動編集を維持したいときは再アップロードと部分修正を使います。
- 文字幅検査は保守的な推定。図形接続・領域・重なり・引用・元データ・保存した本文の構造検査を行いますが、図の意味や描画品質を完全自動判定しません。
- 仕様・部分修正はバージョンとハッシュに紐付く。`approved=true` はスキーマ違反。
- プロジェクト作成から7日で拒否・削除。共有テンプレートは対象外。
- GCP版は今回のPi優先方針により未実装。[移行時の要件](../deploy/GCP.md)。このSQLite版をそのままCloud Runに配置してはいけません。
